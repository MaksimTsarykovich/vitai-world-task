# Кварта — лендинг обжарки кофе

Тестовое задание: одностраничный лендинг маленькой минской обжарки «Кварта» с
рабочей формой заявки. Корзины и онлайн-оплаты нет — менеджер перезванивает и
оформляет заказ.

Исходное ТЗ — <https://tz.vitai.world/>. Спецификация — [`docs/SPEC.md`](docs/SPEC.md).

## Стек

Next.js 16 (App Router, React 19) + TypeScript strict, Tailwind CSS 4 со своими
токенами, Zod (одна схема для клиента и сервера), Vitest. База — SQLite через
`@libsql/client`: файл в томе на VPS или Turso по сети на Vercel, код один и
отличается только `DATABASE_URL`. Запуск: Docker + Compose либо Vercel.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build      # http://localhost:3000, живость — /api/health
```

Без Docker: `cd web && npm ci && DATABASE_URL=file:./data/kvarta.db npm run dev`.
Проверки: `cd web && npm run lint && npm run typecheck && npm test && npm run build`.

Деплой по шагам — [`docs/DEPLOY-VERCEL.md`](docs/DEPLOY-VERCEL.md) (Vercel + Turso)
и [`docs/RUNBOOK.md`](docs/RUNBOOK.md) (VPS + Caddy, эксплуатация).

## Что делали сами, что ИИ

**Сами (заказчик):** постановка задачи и структура лендинга — какие блоки убрать,
оформление подписки свитчером, таблица заказа с количеством и «Итого», два селекта
с зависимыми полями, hero с фото. Макет принят и правлен вручную вместе с
финальными правками (убрана липкая кнопка на мобильных, переименована кнопка
отправки). Визуальная приёмка и деплой — тоже на заказчике.

**ИИ:** спецификация, каркас приложения, макет и дизайн-система, перенос макета в
Next.js, API заявки с дедупликацией и атрибуцией, тесты, скрипты для менеджера,
документация, перенос на Vercel с Turso. Исполнитель кода — OpenCode CLI
(`opencode-go/deepseek-v4.1-flash`), оркестрация и проверки — Hermes Agent.

## Где ИИ ошибался и как это заметили

- **Первый макет:** битые `tel:`-ссылки, подпись «обжарка льном» в шапке, эмодзи в
  `<title>`, контраст подсказки 3.89:1 при норме 4.5:1 и `backdrop-blur`, который
  бриф запрещал. Нашли техническим аудитом: разбор разметки, расчёт контраста по WCAG.
- **Перенос в Next.js:** агент добавил от себя блок «Ближайшая обжарка» и строку
  «Данные тестовые», которых в макете нет, и получил 10 px горизонтального скролла
  на 360 px. Поймали сверкой текста фраза за фразой и замером `scrollWidth`.
- **Вместо правок агент ушёл в свой визуальный QA:** десятки скриншотов в headless
  Firefox, 45 минут на прогон. Прогон прервали и запретили скриншоты — визуальную
  приёмку делает человек.
- **Ошибка оркестратора:** в комментарии к issue #24 написал, что скрипты экспорта
  и бэкапа готовы, хотя их не было. Комментарий отредактирован, скрипты вошли в M4.
- **Миграция через `PRAGMA user_version`:** на локальном файле работает, а Turso
  Cloud такую запись запрещает. Поймали живой проверкой против Turso до деплоя —
  против удалённой базы `GET /api/health` и `POST /api/lead` отдавали 500, то есть
  форма на Vercel не работала бы совсем. Версию схемы перенесли в таблицу
  `schema_migrations`, на запрет PRAGMA есть тест.
- **Тесты зависели от окружения:** при экспортированных `TELEGRAM_*` падали два
  теста «выключено без переменных». Заглушки выставили явно, прогон проверяется
  в трёх режимах окружения.

## Что не успели или сделали бы иначе

- Авторов фотографий с Unsplash подтвердить автоматически не удалось (страницы
  кадров закрыты анти-ботом) — в [`artifacts/issues/23-landing/licenses.md`](artifacts/issues/23-landing/licenses.md)
  стоит «автор уточняется».
- Telegram-дубль включается переменными; без токена он выключен — в репозитории
  лежит только инструкция.
- Сделали бы иначе: часть правок дизайна пришла уже после переноса в Next.js,
  поэтому связку «макет → компоненты» переделывали дважды. Правильнее было
  заморозить макет до старта переноса.
