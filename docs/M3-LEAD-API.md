# M3: POST /api/lead — валидация, дедупликация, атрибуция (issue #24)

Задача: сделать рабочий приём заявок. Сейчас форма в `web/components/form/LeadForm.tsx`
отправляет данные через `submitLead()` в `web/lib/lead-client.ts` — там заглушка с
`TODO(#24)`. Нужно реализовать эндпоинт, хранение, дедупликацию, атрибуцию и
подключить клиент к реальному API.

**Процесс:** правь `web/` прямо в репозитории. Не снимай скриншоты, не запускай
headless-браузер, не создавай копии в `/tmp`, не коммить — оставь изменения в рабочем
дереве и отчитайся. Дизайн и вёрстку не менять, кроме минимальных правок формы под
новый контракт.

## 1. Схема данных (миграция v2)

1. `web/lib/db.ts`: поднять `SCHEMA_VERSION` до 2, добавить в `leads` колонки
   `order_items TEXT` (JSON-массив `[{"slug":"ethiopia","qty":2}]`) и
   `subscription INTEGER NOT NULL DEFAULT 0`.
2. Миграция должна быть идемпотентной и работать на уже существующей базе в томе
   (там `user_version = 1` и таблица без новых колонок): создать таблицу с полным
   набором колонок для чистой базы, а для существующей — добавить недостающие через
   `ALTER TABLE … ADD COLUMN` и выставить `user_version = 2`. Повторный запуск не
   должен падать.

## 2. Контракт `POST /api/lead`

Заголовки: `Content-Type: application/json`, тело не больше 16 КБ.

```json
{
  "name": "Аня",
  "phone": "+375 29 123-45-67",
  "interest": "order",
  "comment": "помол под воронку",
  "subscription": true,
  "items": [{ "slug": "ethiopia", "qty": 2 }, { "slug": "colombia", "qty": 1 }],
  "attribution": {
    "utmSource": "instagram", "utmMedium": "social", "utmCampaign": "october",
    "utmContent": "reels-1", "utmTerm": null,
    "clickIdType": "yclid", "clickId": "1234567890",
    "referrer": "https://www.instagram.com/",
    "landingPath": "/?utm_source=instagram", "pageUrl": "https://example.by/#zayavka"
  }
}
```

Ответы:

| Код | Тело | Когда |
|---|---|---|
| 201 | `{"status":"ok","id":42,"requestId":"…"}` | заявка сохранена |
| 200 | `{"status":"duplicate","id":41,"requestId":"…"}` | тот же нормализованный телефон за последние 10 минут |
| 400 | `{"status":"error","code":"VALIDATION","fields":{"phone":"…"},"requestId":"…"}` | ошибка полей |
| 413 | `{"status":"error","code":"PAYLOAD_TOO_LARGE"}` | тело > 16 КБ |
| 429 | `{"status":"error","code":"RATE_LIMIT"}` + заголовок `Retry-After` | больше лимита запросов с IP |
| 500 | `{"status":"error","code":"SERVER","requestId":"…"}` | исключение/БД |

`GET /api/lead` → 405 с заголовком `Allow: POST`.

## 3. Валидация

3. Общая Zod-схема в `web/lib/lead-schema.ts` (используется сервером; клиент может
   переиспользовать для подсветки полей).
4. Имя: `trim`, 2–80 символов, без управляющих символов. Ошибка: «Укажите имя
   (2–80 символов)».
5. Телефон: только белорусский. Принимаем `+375…`, `375…`, `80…`, `0…` и локальные
   9 цифр, с пробелами/дефисами/скобками. Нормализация в `web/lib/phone.ts` к
   `+375XXXXXXXXX`; коды `25/29/33/44` и минский `17`; остальное — ошибка с
   подсказкой «Введите белорусский номер: +375 29 123-45-67».
6. Интерес: `question` | `order`.
7. Комментарий: `trim`, до 1000 символов. Если `interest = "question"` — обязателен
   и непустой («Напишите вопрос»).
8. Заказ: если `interest = "order"`, массив `items` обязателен и непуст; элементы
   только из четырёх слагов (`ethiopia`, `colombia`, `brazil`, `drip`), `qty` —
   целое 1–10, дубли слагов складываются в количестве. `subscription` —
   необязательный булев (по умолчанию `false`).
9. Атрибуция: строки, обрезаются по лимитам (utm — 200, click id — 512,
   referrer/page_url/landing_path — 1000, user_agent — 500), управляющие символы
   вырезаются. Если клиент ничего не прислал — fallback на заголовки `Referer` и
   `User-Agent`.
10. Ответ валидации: словарь `fields` с русскими сообщениями по каждому полю,
    без stack trace и SQL.

## 4. Дедупликация (10 минут)

11. Окно — скользящие 10 минут по нормализованному телефону. Вставка атомарная:
    `BEGIN IMMEDIATE` + `INSERT … SELECT … WHERE NOT EXISTS (…) RETURNING id`.
    Если строка не вставилась — возвращаем `200 {status:"duplicate"}` и `id`
    существующей заявки.
12. Один и тот же номер после 10 минут создаёт новую заявку.
13. Тесты: граница окна (9:59 / 10:01 через явный `created_at`), конкурентные
    вставки (10 параллельных промисов → одна строка), два разных телефона → две
    строки.

## 5. Атрибуция на клиенте

14. `web/lib/attribution.ts` — при первом заходе сохраняет в `sessionStorage`
    (`kvarta:attribution`): `utm_*`, `yclid`/`gclid`/`fbclid`, `referrer`,
    `landingPath`. При отправке добавляет `pageUrl`. Cookies не используем.
15. `submitLead()` в `web/lib/lead-client.ts` шлёт реальный `POST /api/lead`:
    `AbortController` с таймаутом 12 с, `Content-Type: application/json`, передаёт
    `name`, `phone`, `interest`, `comment`, `subscription`, `items` и `attribution`.
16. Обработка ответов в форме: `201` — панель «Заявка принята — перезвоним»;
    `200 duplicate` — «Заявка уже принята»; `400` — ошибки под полями
    (`aria-invalid`, фокус на первом); `429` — «Слишком много попыток, позвоните
    нам»; `5xx`/сеть/таймаут — плашка с «Попробовать ещё раз» и контактами.
    Кнопка блокируется на время запроса, введённые данные не теряются.

## 6. Ограничения и защита

17. Лимит тела: 16 КБ по `Content-Length` и по фактической длине → 413.
18. Rate limit: в памяти процесса, окно 1 минута, по умолчанию 20 запросов с IP
    (env `LEAD_RATE_LIMIT`). IP — из `X-Forwarded-For` при `TRUST_PROXY=1`, иначе
    из соединения. При превышении `429` + `Retry-After`.
19. Логи: `requestId` (`crypto.randomUUID()`), код ответа, длительность, телефон
    в маскированном виде (`+375 29 ***-**-67`), без имени и текста комментария.
    `requestId` также в заголовке ответа `X-Request-Id`.
