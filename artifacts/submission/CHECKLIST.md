## 3. Плюсы из ТЗ

- [~] Дублирование заявки в Telegram — код готов, включается переменными
      `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`; без них тихо выключено. Проверено с
      неверным токеном: заявка сохраняется, в логе `[telegram] отправка не удалась`.
- [x] OG-превью: картинка 1200×630 (AVIF/WebP для картинок страницы, PNG для OG),
      заголовок и описание, canonical, JSON-LD `LocalBusiness`.
- [~] Анимации: анимации появления блоков убраны ради производительности (первый
      замер Lighthouse показал лишний вес и поздний LCP) — остались переходы при
      наведении и `prefers-reduced-motion`. Карта грузится по клику, чтобы не тянуть
      4.5 МБ тайлов и сторонние cookie на первой загрузке.

## 3.1. Производительность (Lighthouse mobile, прод-сборка)

| Метрика | Значение | Цель в спеке |
|---|---|---|
| performance | 93 | ≥ 90 ✅ |
| accessibility | 100 | ≥ 95 ✅ |
| best-practices | 100 | ≥ 95 ✅ |
| SEO | 100 | 100 ✅ |
| TBT | 100 мс | < 200 мс ✅ |
| CLS | 0 | < 0.1 ✅ |
| LCP | 3.1 с | < 2.5 с — **отклонение** |

Отклонение по LCP: замер идёт в симуляции медленной сети (slow 4G, ×4 CPU). В
реальном браузере без троттлинга LCP-элемент (hero-картинка в AVIF, 25 КБ) грузится
за ~0.35 с, TTFB 14 мс. Симуляция добавляет к этому шрифты и модель сети. Путь к
2.5 с — ещё сжать шрифты и отдавать hero-вариант 640 px вместо 750 px, но дальше
режем качество картинки на DPR 1.75+.
